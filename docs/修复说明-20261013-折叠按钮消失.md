## 一、症状

1. 历史消息（AI 回复与用户输入）下方的胶囊键 `展开全文 · 还有 N 行` / `展开我的输入 · 还有 N 行` **全部消失**，消息也不再折叠。
2. 同一个界面里，工作步骤的圆形折叠键**一切正常**（那是另一条代码路径，不经过本 bug）。
3. 现象看起来「时好时坏」：有的消息有按钮、有的没有。

## 二、根因（代码实证，非推测）

**下刀位置的计算丢掉了「保留行数」这个限制。**

折叠判定是 `overflows`，它决定「折还是不折」「胶囊键显不显示」：

```js
// src/browser.js — measureAndClamp()
const natural = probe.natural
const cutHeight = probe.cutHeight > 0 ? probe.cutHeight : contentBudget
const overflows = natural > cutHeight + 8
```

- `natural`：内容自然高度（正确）。
- `cutHeight`：**下刀位置**，语义是「保留预算之内的最后一行底部」。
- `overflows`：内容是否真的超出保留行数。

病根在 `probeNatural()` 里算下刀位置的那个 `pick()` —— 它 **没有拿到这一侧的保留行数**，于是取的是「所有行的最底部」：

```js
// 修复前（错）：取所有行的最底部 = 内容总高度
const pick = (ends) => {
  let cut = 0
  for (const end of ends) {
    if (end <= 0) continue
    if (cut === 0 || end > cut) cut = end   // ← 没有预算上限
  }
  return cut
}
```

内容总高度 ≈ `natural`，代入判定式：

```
overflows = natural > natural + 8   // 恒为 false
```

于是**既不折、也不给按钮**（`measureAndClamp` 在 `overflows` 为假时把胶囊键 `hidden`）。

### 为什么只有一部分消息中招

同一份代码里有两条测量路径，只有一条丢了预算：

| 路径 | 何时走到 | 下刀位置算法 | 结果 |
|---|---|---|---|
| `probeNatural()`（克隆测量） | 真实浏览器正常布局时**一定**走这条 | `pick()` **无预算** | 恒判「不溢出」→ 丢按钮、不折 |
| `probeNaturalFallback()`（真实节点降级） | 只在克隆量不到几何时（jsdom / 测试替身） | `cutHeightForBody(body, budget)`，**带预算** | 判定正确 |

真机计数（2026-10-13，用户会话）：`probe: { cloneOk: 33, cloneNull: 47, fallback: 47 }` —— 33 条走克隆的全部丢按钮，47 条降级到真实节点测量的正常。这就是「时好时坏」的真身。

### 这个参数是什么时候丢的

`f02a2e3`（测量改走屏幕外克隆）把原来带预算的 `cutHeightFor(body, budget)` 并进了 `probeNatural()`，但**没有把 `budget` 一起带过去**。随后两次修复方向都偏了：

- `714df50`「修克隆测量的三处失真」：修的是容器宽度、克隆宽度、`padding-bottom` 重复计算 —— 都是「量得准不准」；
- `36502d6`「撤掉 natural 上重复计算的 padding-bottom」：同上。

病根在「**拿量出来的数做什么比较**」，不在「量得准不准」，所以那两次怎么修都不见效。

## 三、修复

```js
// 修复后：下刀位置只接受「预算之内」的行底部，取其中最大者
const budget = F.clampHeightFor(budgetLines, lineHeight) + mediaHeight
const pick = (ends) => {
  let cut = 0
  for (const end of ends) {
    if (end <= 0) continue
    if (end > budget) continue          // ← 预算之内
    if (cut === 0 || end > cut) cut = end
  }
  return cut
}
```

- `probeNatural(body, budgetLines)` 新增第二参数（本侧保留行数），与 `probeNaturalFallback` 的 `cutHeightForBody(body, budget)` 判据完全一致。
- 两个调用点都显式传预算：`measureAndClamp()` 传本侧生效行数（`collapseAll` 时用 `collapsedLines`），`labelFor()`（算「还有 N 行」文案）同理。
- 一行都放不下时 `cut` 为 0，由调用方用 `contentBudget` 兜底（与降级路径行为一致）。

### 顺带修掉的第二个缺陷：`overflows` 两侧不同量纲

```js
// 修复前：左边含内边距、右边不含
const overflows = natural > cutHeight + 8
```

- `natural` 是 `scrollHeight`（含上下内边距）；
- `cutHeight` 按 `box-sizing` 换算（`content-box` 下只到内容框）；
- 两者差 `padding-top + padding-bottom`（实测 16px）。

后果：**一行文字、根本超不过 10 行预算**的消息也被判成溢出 —— 白出一个按钮并裁掉 8px，README 承诺的「短消息不折」其实从未在真实布局下成立。现在比较前把内边距补回去（两侧同量纲）；降级路径也补齐 `padTop` / `padBottom` / `boxSizing` 字段，两条路径字段集一致。

## 五、教训（写给下一次）

1. **浏览器专项原先只核对高度和宽度，不检查下刀位置**，这个 bug 正是从它眼皮底下溜过去的（当时 7/7 全绿）。已补三条检查（下刀位置落在预算内、长文本必须溢出、短文本必须不溢出）——以后任何改动测量逻辑都必须跑它。
2. **「测试全绿」不等于「功能正确」**：137 个单元测试用的 fake DOM 不产出布局，`probeNatural` 在它上面直接返回 null 走降级路径，而**降级路径恰好是对的** —— 于是单元测试永远测不到出问题的那条路径。
3. **两条并行路径必须同判据**：克隆路径与降级路径长期不一致（一条带预算、一条不带），是这次 bug 藏了这么久的结构性原因。改动其中一条时，必须同时核对另一条。
4. **真机计数比反复猜有效**：`stats()` 里临时加的探针计数器（`probe.cloneOk/cloneNull/fallback`、`side.*`）一次就定位到了「哪些消息走哪条路径」，比连续三轮盲改省下大量时间。计数器保留在代码里，随时可用。

## 六、附：同期修掉的另一个真问题（AI 回复被整体跳过）

排查初期真机计数显示 `skipAncestor: 37739` —— 宿主更新后把 `assistant-step` 回复行包进了过程容器（`[data-turn-process]` / `[data-step-process]`），而 `skipReason()` 用的是「整张祖先标记表」，于是把回复行当成过程内容跳过了。

修法：把标记表拆成「容器类」与「标记类」。

- `SKIP_CONTAINERS`（`data-turn-process*` / `data-step-process*`）：宿主把过程与回复放在一起的结构容器，**不再**成为跳过消息行（`user` / `assistant-step`）的理由 —— 消息行自身的 `flow-kind` 已经证明它是正文。
- `SKIP_MARKERS`（隐藏过程成员 `data-turn-process-hidden`、答案桩 `data-turn-process-answer`、上下文注入、系统提示、错误行、附件等）：**仍然**生效（`closest` 从锚点自身开始匹配，锚点自身带标记同样命中）。

真机验证：`skipAncestor: 37739 → 0`，`clamped: 1 → 32`。

> 记录在案的一次无效尝试：期间曾把 `messageBodyOf()` 的助手分支改成「锚点浅层内文本最多的 div」启发式，结果可能取错正文节点、把按钮插到错误位置，已回退为原契约实现。结论：**在没有真机 DOM 证据前，不要用启发式替换确定性契约。**
