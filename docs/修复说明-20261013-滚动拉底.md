## 一、症状

用鼠标滚轮往上翻历史对话，会被**强制拉回到最新一条**（界面最底部）。每次必现。

## 二、根因（实测定位，非推测）

**没有任何代码在"滚"你。** 是你的视口被内容高度的抖动挤到了底部。

病根在 `src/browser.js` 的 `measureAndClamp()`：为了量一条消息的**真实高度**，它必须先在真实节点上解除 `max-height` 限制，量完再夹回去：

```js
// 修复前的代码
removeAttr(body, 'data-lf-clamped')     // ← 解除，内容瞬间展开到完整高度
const natural = body.scrollHeight       // ← 这时才量得到真实值
const cutHeight = cutHeightFor(body, contentBudget)
...
setAttr(body, 'data-lf-clamped', '1')   // ← 夹回去
```

代码注释自己写明了为什么必须这样：

> Measurement must happen while the body is NOT clamped, otherwise `scrollHeight` reflects the constrained box instead of the real content.

（被 `max-height` 夹住的盒子，`scrollHeight` 量出来是裁剪值，不是真实内容高度。）

**而这个测量每秒都在跑**：

```
src/client-entry.js:679   setInterval(pull, 1000)          // 每秒
        ↓
src/browser.js:665        turnTimers.subscribe(() => schedule())
        ↓
src/browser.js:1962       schedule() → requestAnimationFrame(scan())
        ↓
src/browser.js:1945       scan() → measureAndClamp() → 解除/夹回
```

于是「展开 → 夹回」**每秒发生一次**，对话总高度跟着每秒抖一次：

- 内容突然变高 → 你在历史区的视口被推离原处
- 内容突然变矮 → **你超过了新的总高度，浏览器把你钳到能显示的最底部**

后者就是"被强制拉到最新一条"。配合 CSS 里的 `transition: max-height .18s ease`，视觉上不是"跳一下"，而是"被慢慢吸下去"。

### 为什么之前没发现

不滚上去就只在底部附近，高度抖动看不出影响；只有**往上翻看历史**时才被挤下来。而且插件关掉就好、开装就复现，所以能确定是它。

### 附带发现的第二个 bug（同一病根）

`labelFor()` 用 `body.scrollHeight`（裁剪值）当"内容总高"算「还有 N 行」：

```js
const lines = F.hiddenLineLabel(body.scrollHeight, body.getBoundingClientRect().height, ...)
```

裁剪后 `scrollHeight ≈ 可见高度`，所以隐藏行数被**严重低估**——按钮上写"还有 3 行"，实际可能还有 30 行。

## 三、修复方案（根治，非缓解）

### 核心：屏幕外克隆测量

新增 `probeNatural(body)`：把 `body` **克隆一份**，塞进一个屏幕外容器（`position:fixed; left:-99999px; visibility:hidden`），在克隆上量 `scrollHeight` / `Range.getClientRects()`，量完删除克隆。

**真实节点从头到尾带着 `max-height`，一秒都不被解除，布局零扰动。**

关键实现细节：

1. **克隆要解除自己的钳制**（`clone.removeAttribute('data-lf-clamped')` + 清掉内联 `max-height`/`height`/`padding-bottom`），否则量到的还是裁剪值——但这发生在屏幕外节点上，不影响真实布局。
2. **克隆的宽度必须与真实节点一致**，否则换行位置不同、高度没有意义（`clone.style.width = realBox.width + 'px'`，同时继承 `boxSizing`）。
3. **克隆容器复用同一个实例**（`measureHostOf()`），避免每次扫描都创建/销毁 DOM。
4. **`finally` 里必须移除克隆**，否则会一直占着测量容器。
5. **附件高度同样在克隆上量**（`mediaHeightIn(clone)`），判据只看几何，对克隆同样有效。

### 附带修复

| 改动 | 原因 |
|---|---|
| `labelFor()` 改用 `probe.natural` | 修「还有 N 行」严重低估 |
| 删掉 `transition: max-height .18s ease` | 根治后已无抖动源，transition 只会把残余变化拉成渐变，看上去更像"被吸下去" |
| `scan()` 的 signature 改用 **纯内容指纹** `contentSignature()` | 见下 |
| 删除死代码 `cutHeightFor()` | 其职责已并入 `probeNatural` / `cutHeightForBody()` |

### 为什么 signature 也必须改

原来的 fingerprint 是 `${record.body.scrollHeight}|...`——**算指纹本身就要测量**。在克隆不可用的环境里，这次测量会退化成"解除→还原"，每轮白写 4 个属性，被插件自己的 MutationObserver 当成变化 → 触发下一轮扫描 → **自我喂食循环**（测试 `a settled conversation produces no further DOM writes` 抓到：空闲时 user body 被重写 30 次）。

`contentSignature()` 只用**零成本的只读信息**：子元素个数 + 文本总长度 + 生效的行数预算 + extraPx + tail 显隐。这五者任一变化，几何才可能变；都不变就一跳而过，**连量都不量**。

### 降级路径（`probeNaturalFallback`）

克隆量不到几何时（判据：克隆 `width`/`height` 为 0，或 `scrollHeight` 为 0 —— 典型是 jsdom / 测试用的 fake DOM，它们不产出真实布局）→ 回退到直接在真实节点上量，保留旧的"解除→夹回"行为。

**这条路在真实浏览器里永远不会走到**，所以不会把抖动带回来；它的存在只是为了让不做布局的环境依然能夹断、依然能算得出「还有 N 行」。回退时也做了同值短路，不产生无谓写入。
