# 回归检查清单（老 bug 专项）

> **这个文件是给「下一个接手这个插件的 AI」看的。每一次改动都必须从头到尾过一遍。**
>
> 这个插件反复踩同一批坑：**它是一条 DOM 契约路线**——宿主（DSH 桌面应用）会更新，
> 契约会漂移，而插件里每一条"联动宿主的机制"都可能在某次宿主升级后静默失效。
> 下面每一条都是**真实发生过、且多数复发过不止一次**的事故，不是理论风险。
>
> ## 改完代码必须做三件事
>
> 1. **跑自动检查**：`node scripts/regression-check.mjs`（逐条对应本清单，全绿才算过）
> 2. **跑真实浏览器专项**：`node test/probe-natural-browser.mjs`（它会启动无头 Chrome）
> 3. **逐条阅读本清单**，确认这次改动没有把下面任何一道防线拆掉
>
> ## 三条铁律（违反必复发）
>
> - **改了 `src/` 必须重建 `client.js`**：宿主加载的是 `client.js`（构建产物），
>   不是 `src/`。2026-10-13 整整一轮修复因为"改了源码没重建"而完全没生效，
>   用户看到的现象是"你修了半天什么都没变"。
> - **测试全绿 ≠ 功能正确**：155 个单元测试跑在假 DOM 上（不产出布局），
>   真实布局路径（克隆测量）根本不在覆盖范围内。真实浏览器专项才是这条路径的守卫。
> - **没有真机证据，不要用启发式替换确定性契约**：曾把 `messageBodyOf()` 换成
>   "找文字最多的 div"，结果取错节点、把按钮插到错误位置，只能回退。
>   拿不到真机 DOM 时，先埋探针计数（`stats()` 已内置两组）再改。

## 一、界面卡住类（用户直接受害，最严重）

### 1. 右栏收起后，会话区不回弹（停在半宽）
**复发过一次（0.9.5 修，2026-10-13 再犯）。**

- 症状：关闭右侧栏 / 进入全屏后，主对话区仍然只占一半宽度，右边一片空白。
- 根因：为了把右栏钉到设定宽度，插件写了一条 `!important` 的 `grid-template-columns`
  规则。宿主收起右栏时只把第三列设为 0（或者干脆把面板内容卸掉），**那条规则仍然
  占着第三列**，于是主区被挤在半宽。
- 现在的四道防线（缺一条就会复发）：
  1. **纯 CSS 自我失效**（最强、零延迟）：规则选择器是
     `[data-lf-frame]:not([data-rightbar-collapsed]):not([data-rightbar-fullscreen])`
     —— 宿主一打收起/全屏标记，CSS 立刻不再匹配。
  2. **观察整棵文档**（不是某一个元素）：宿主重渲染会把 AppFrame 整个换掉，
     绑在旧节点上的观察者会永远失灵。回调里只做廉价过滤，避免插件自己的 style 写入造成噪声。
  3. **盯框架的直接子节点**（`childList: true`）：右栏被卸载/替换时靠它响应。
  4. **几何自检**（1.2s 一次，只在强制生效时）：右栏那一列里连续两次看不到
     "真正渲染出来的后代"就撤规则；页面隐藏时跳过；只在本地读几何、不写 DOM。
- 另外：**插件总开关关闭**与 **dispose** 都必须撤规则（`clearOverride()`）。
- 测试：`test/entry.test.mjs` 三条 —— `closing the right panel releases...`、
  `the forced-width rule releases itself in pure CSS...`、
  `a right panel whose content disappears releases the forced width`。
- **检查动作**：改右栏相关代码后，手动试三种收起方式：点收起按钮、进全屏、把面板内容切空。

### 2. 往上翻历史被强制拉回最新一条
**复发过一次（`f02a2e3` 根治，`f02a2e3` 之前的版本必现）。**

- 症状：滚轮往上翻历史对话，视口被顶回底部，每次必现。
- 根因：为了量消息的真实高度，旧代码在**真实节点**上解除 `max-height` 量完再夹回；
  而这个测量由每秒一次的扫描驱动 —— "展开→夹回"每秒一轮，对话总高度抖动，
  浏览器把读者视口钳到底部。
- 防线：测量必须走**屏幕外克隆**（`probeNatural()`），真实节点全程带着 `max-height`
  不动。降级路径（`probeNaturalFallback()`，只给不产出布局的假 DOM 用）允许在真实
  节点上临时解除，但必须在 `finally` 里还原，且同值不写。
- 测试：`test/probe-natural-browser.mjs` 的「测量两次后真实节点几何零变化」。

### 3. 折叠胶囊键消失、消息不再折叠
**复发过一次（0.10.2 修）。**

- 症状：消息下方的 `展开全文 · 还有 N 行` / `展开我的输入 · 还有 N 行` 消失，
  消息也不折；而工作步骤的圆形折叠键正常（另一条代码路径）。
- 根因：折叠判定 `overflows = natural > cutHeight + 8`。克隆测量里算下刀位置
  （`cutHeight`）的 `pick()` **丢掉了这一侧的保留行数**，取的是"所有行的最底部"
  = 内容总高度，于是判定式恒为假 → 既不折、也不给按钮。**参数是重构时丢的**。
- 防线：
  1. `probeNatural(body, budgetLines)` 必须接收保留行数，`pick()` 只接受
     `end <= budget` 的行底部（与 `cutHeightForBody()` **同一判据**）。
  2. **两条测量路径必须同判据、同字段集**：克隆路径与降级路径长期不一致，
     是这个 bug 能藏住的结构性原因。
  3. `overflows` 两侧必须**同量纲**：`natural` 是 `scrollHeight`（含上下内边距），
     `cutHeight` 按 `box-sizing` 换算 —— 比较前要补回内边距，否则一行短消息
     也会被误判成溢出（README 承诺的"短消息不折"就是这么失守的）。
- 测试：`test/probe-natural-browser.mjs` 三条 —— 下刀位置落在预算内且非零、
  长文本 `overflows` 必须为真、短文本必须为假。**这个专项原先只核对高度和宽度，
  这个 bug 正是从它眼皮底下溜过去的。**

### 4. 宿主更新后，消息行被整体跳过（AI 回复永不折叠）
**2026-10-13 出现。**

- 症状：只有自己的输入能折，AI 回复一律不折。
- 根因：宿主把消息行包进了过程容器（`[data-turn-process]` / `[data-step-process]`），
  而 `skipReason()` 用的是"整张祖先标记表"，于是把回复行当成过程内容跳过了
  （真机计数：`skipAncestor` 三万七千次）。
- 防线：标记表拆成两类 —— **容器类**（过程容器）不再成为跳过消息行的理由
  （消息行自身的 `flow-kind` 已证明它是正文）；**标记类**（隐藏过程成员、答案桩、
  上下文注入、系统提示、错误行、附件）仍然生效（`closest` 从锚点自身开始匹配）。
- 排查入口：`__DSH_BUBBLE_FOLD__.stats().side` 会告诉你助手/用户输入各自卡在哪一步。

### 5. 滚轮滑过折叠消息就被展开
- 根因：折叠盒曾是可滚动容器，且"任何滚动就算有人要读里面 → 自动展开"。
- 防线：折叠盒必须是**纯裁切**（`overflow: hidden`），不是滚动容器；不监听滚动展开。
  查找面板揭示命中时自己展开（`revealAt`）。

### 6. 关闭右栏后插件仍占着那一列（与第 1 条同源，单独列出因为最容易漏）
- 防线：`settings.enabled === false`、`dispose()`、检测到收起/全屏/第三列为 0 —— 四条路径都必须 `clearOverride()`。

## 二、启动与崩溃类（会让整个 DSH 起不来）

### 7. `apply()` 抛错 = 整个应用起不来
**出现过一次（0.9.2）。**

- 症状：DSH 启动弹"应用无法启动"对话框，日志写
  `web boot: 1 entry did not activate / dsh-fold-polish: failed`。
- 根因：本插件的客户端行是 `dsh.client.immediately`（属于启动图）。
  受限 ctx **用属性访问未声明的服务会直接抛错**（不是返回 undefined），
  例如 `ctx.sidebarRightTabs`。
- 防线：
  1. 查服务一律 `try { ctx.get(name) } catch { null }`，**不要用属性访问**；
  2. `inject` 里必须点名要用到的服务；
  3. `apply` 外层兜底 try/catch —— **任何异常都只降级停用本插件**。
- 测试：`test/entry.test.mjs` 的「敌意 ctx」用例守着这条线。

### 8. `index.js` / `factory` 的两种启动事故
- `index.js` 必须以合法 ESM 被 `import()` 解析（曾写成 Python 风格 `#` 注释 → 宿主
  报 `failed to import`）。
- `factory` **不能声明 `require` 参数**（会遮蔽包内自己的 `require`，报
  `missed the module table`，桌面端表现为"应用无法启动"）。正确写法 `factory: () => {}`。

### 9. 改名改坏 CSS 作用域
**出现过一次（0.9.4）。**

- 症状：整套 CSS 失效，控件退化成浏览器默认的巨型灰块按钮。
- 根因：改名时把 CSS 里的 `:root[data-dsh-bubble-fold]` 一起替换了，而设置该属性的
  常量没动。
- 防线：CSS 的 `:root[...]` 必须与 `ROOT_ATTRIBUTE` 完全一致。
- 测试：`test/entry.test.mjs` 的静态比对用例。

## 三、构建与数据链类

### 10. 改了 `src/` 没重建 `client.js`
**2026-10-13 真实发生，浪费了一整轮。**

- 症状：修复"好像做了"，但用户界面上毫无变化。
- 防线：`node scripts/build.mjs --check` 必须通过；提交时必须把 `client.js` 一起提交。
- 检查动作：`node scripts/build.mjs --check`（脚本里已含）。

### 11. 构建脚本里的手写注册表不同步
**出现过一次（0.10.1 的 turn-timer 永不显示）。**

- 根因：`build.mjs` 的 MODULES 注册表是手写清单，加了模块只更新了清单没更新注册表 ——
  模块打进包却查无此键，而 `--check` 比对不出来（产物与构建脚本同步，bug 在模板里）。
- 防线：注册表按 `LOCAL_MODULES` **自动生成**，加模块只改一处。
- 测试：`test/turn-timer-wiring.test.mjs`。

### 12. 猜测宿主的数据形状
**出现过一次（0.10.1 的 `pickSessionId`）。**

- 根因：猜了三种 `sessions` 形状，在真实宿主里全不存在。
- 防线：**用宿主实证路径**（DOM `[data-conversation-session]` +
  `sessions.list.getSnapshot().byId`），不要凭空猜对象形状。
- 附带教训：诊断对象必须挂在**真实 window**上，写在传入的环境对象上会导致控制台读不到。

### 13. 每轮小字重复插入几百次
**出现过一次（0.10.1）。**

- 根因：宿主把 `data-chat-turn` 挂在**每条消息容器**上，插件按属性逐个插入。
- 防线：先按 turn 分组，只在**该轮 DOM 末尾容器**插一个。

### 14. 右栏拖动的值被自己写回设置
- 根因：自己 apply 宽度时会触发宿主重渲染，被误当成"读者拖动"。
- 防线：`lastAppliedAt` **800ms 门闩**；差异 ≤2px 视为自己的应用。

## 四、其它已修但容易重犯

### 15. 图片被算进行数预算
- 症状：「一张图 + 几行字」也被折叠，读者看不到自己刚发的内容。
- 防线：附件高度**单独**计入可见预算，行数预算只花在文字上；图片永远完整、只切文字。

### 16. 打印时内容仍是折的
- 防线：`@media print` 里展开所有折叠 + 隐藏所有插件控件；
  `hidden="until-found"` 的步骤行在打印媒体下要 `display: revert`。

### 17. 全局快捷键与浏览器/输入法冲突
**出现过一次（`Ctrl+Shift+B` 与"显示/隐藏书签栏"同键，被误关过）。**

- 防线：**插件不注册任何全局快捷键**（0.10.1 起全部移除），所有开关走设置界面。
- 测试：`test/entry.test.mjs` 的「no global keyboard shortcuts」用例。

## 五、怎么用这份清单（给下一个 AI 的操作流程）

1. 动手前：读本文件 + `DEVELOPING.md`，知道哪些机制是"联动宿主"的脆弱点。
2. 改动中：只要碰了**测量逻辑**、**右栏宽度**、**跳过判定**、**构建脚本**、**CSS 作用域**，
   就必须同时看本清单里对应的那一条，确认没拆掉防线。
3. 改完：`node scripts/regression-check.mjs` → 必须全绿。
4. 交付前：用户没在真界面确认，就不算修好（**测试全绿不算验证**）。
5. 复发时：**先把真机证据拿到手**（`stats()` / `test/diagnose.js` / F12 控制台），
   再改代码。没有证据就改代码 = 大概率又是一轮空转。
